# AI 自动打标

BiliShelf 的 AI 打标是一套**独立于 B 站原始标签**的本地标签体系：用封面 + 视频帧调用视觉模型（VLM），按「标签方案」生成带分类和置信度的标签；结果先进入审核页，通过后才进入侧栏「本地标签」。

> 只有你主动发起任务时才会把图片/音频上传到你配置的第三方服务；不会后台自动上传。

---

## 1. 快速开始

1. 打开左侧「AI 打标」。
2. 在「模型与工具」里添加一个 Provider，填入 Base URL、模型名和 API Key，点「测试连接」。
3. 在「标签方案」里确认默认方案，或去「库级分析」让 AI 生成一套。
4. 点右上角「开始打标」，选择范围，确认上传提示。
5. 到「标签审核」逐条/批量通过；通过的标签会出现在侧栏「本地标签」。

首次启动会自动创建一个「通用方案」，可以直接用，也可以复制后修改。

## 2. 模型 Provider

### 2.1 支持的协议

| 协议 | 说明 | ACRCloud 工具 |
| --- | --- | --- |
| OpenAI 兼容 | 大多数网关、官方 OpenAI、通义、智谱、硅基流动、Ollama、LM Studio | 支持 |
| Anthropic Messages | Claude 官方或兼容网关 | 支持 |
| Google Generative AI | Gemini 官方 API | 支持 |
| 自定义 | 可选 OpenAI / Anthropic / Gemini 兼容端点，或纯模板模式 | 兼容端点支持；纯模板不支持 |

> 「OpenCode Go」等 OpenAI 兼容网关选「自定义 → OpenAI 兼容端点」即可，工具调用可用。

### 2.2 预设

「添加 Provider」弹窗里有快速预设：

- 通义千问 VL（`qwen-vl-max`）
- OpenAI（`gpt-4o-mini` 等视觉模型）
- Gemini（`gemini-2.5-flash` 等）
- Anthropic（Claude）
- OpenRouter
- 硅基流动
- Ollama / LM Studio（本地）
- OpenCode Go（OpenAI 兼容）
- DeepSeek（文本模型，不支持视觉，仅可用于库级文本分析）

预设只是示例，模型名和 Base URL 都可改。DeepSeek 目前没有公开视觉 API，不要用它做逐视频打标。

### 2.3 关键参数

- **API Key**：留空表示不修改；勾选「清除」才会删除。Key 使用 Electron `safeStorage`（Windows DPAPI）加密保存在 `userData/ai-config.json`，渲染进程只能看到末 4 位。
- **能力**：视觉、工具调用、JSON 模式、音频。工具调用关闭后不会向模型暴露 ACRCloud 工具。
- **图片细节**：`low` 省 tokens，`auto` 平衡，`high` 更清晰但更贵。
- **请求头**：留空保持已有；填写 JSON 会整体覆盖，值加密保存。
- **测试连接**：发一张 1×1 PNG +「只回复 OK」；文本模型会退回纯文本测试，并提示视觉不可用。测试输出上限已提高，避免推理模型把 token 全用在 reasoning 上。
- **探测模型**：模型名旁的「探测」会读取 `GET /models`。OpenCode Go 等返回丰富元数据的网关会自动填入视觉、工具、JSON、输出上限和价格；选择检测到的模型即可切换并自动应用能力。普通 OpenAI 兼容网关通常只返回模型 id，视觉/工具/JSON 仍需手动确认。

## 3. ACRCloud（可选）

用于识别 BGM。没有配置时，AI 仍会使用标题、简介和 B 站原始标签推断 BGM，但不会编造曲名。

1. 在 ACRCloud 控制台创建 **AVR 项目**，拿到 Host、Access Key、Access Secret。
2. 填入「模型与工具 → ACRCloud BGM 识别」，启用并保存。
3. 点「保存并测试」：发送 3 秒静音样本，返回 `1001 No result`，或安静音无法生成指纹的 `2004`，都视为鉴权成功。

> 控制台「个人访问令牌（JWT）」用于 Console API，不能直接当作识别接口的 Access Secret。识别仍需要 AVR 项目的 Host / Access Key / Access Secret；如果账号下没有 AVR 项目，控制台令牌也无法完成 BGM 识别。

工作方式：

- 模型只在画面/原始标签明显是音乐、舞蹈、演奏、翻唱、MV 时调用 `identify_music`。
- 每次运行最多调用 3 次（start / middle / end）。
- 主进程抽取 15 秒单声道 MP3，按音频 hash 缓存结果。
- 识别成功后会生成曲名、艺术家、流派三类标签，来源标记为 `ACR`。

## 4. 标签方案

一个方案包含：

- **关注点**：人物形象、服饰、动作、场景、风格、BGM、情绪，也可自定义（如菜系、烹饪方法、器材）。
- **分类体系**：分类名 + 说明 + 示例标签；AI 输出的标签必须归入这些分类。
- **系统提示词**：约束模型只根据画面打标、不要编造、只输出 JSON。
- **用户模板**：可用变量：
  `{{title}} {{upName}} {{duration}} {{sourceName}} {{description}} {{originalTags}} {{bgmHint}} {{focus}} {{taxonomy}} {{maxTags}} {{minConfidence}} {{language}} {{frameTimestamps}} {{schema}}`
- **输出约束**：最多标签数、最低置信度、语言。
- **ACRCloud / B 站标签开关**。

作用域：

- **全局方案**：默认方案，整个库使用。
- **来源方案**：为某个收藏夹/来源覆盖全局方案；一个来源最多一个。

「预览提示词」会用示例视频数据渲染模板，方便检查变量和分类。

## 5. 开始打标

范围：

- 整个素材库（仅已下载且文件存在）
- 当前筛选结果
- 指定来源
- 选中视频

选项：

- **强制重跑已打标视频**：关闭时会跳过同方案已完成的视频。
- **最多处理条数**：留空不限制。

首次对某个外部 host 发起任务时会弹出上传确认，列明 Provider / ACRCloud host；确认后写入 `ai-config.json` 的 `consent.hosts`，新 host 首次使用会再次提示。本地 Ollama / LM Studio 不会触发外部上传确认。

## 6. 标签审核

审核页默认显示「待审核」，每条运行展示：

- 封面、标题、UP、来源、方案、模型、时间、tokens。
- 原始标签（手动 / 平台自动）。
- 抽取帧（封面 + 3 帧，可点击放大；可在播放器中打开）。
- AI 标签，按分类分组，带置信度和来源（VLM / ACR / B站 / 推断）。

操作：

- 勾选标签 →「通过所选」/「拒绝所选」。
- 勾选整行 →「批量通过」/「批量拒绝」/「重跑」。
- 通过后标签变绿；拒绝后置灰，可点「恢复」回到待审核。
- 标签可内联编辑名称/分类/置信度，也可添加/删除。
- 「全选当前页」只选当前筛选结果；批量操作前请确认筛选条件。

通过后：

- 写入 `ai_tags` / `video_ai_tags`。
- 侧栏「本地标签」出现该标签。
- 搜索与 AI 标签筛选可命中。
- 写入该视频 `metadata.json` 的 `aiTags` / `aiTaggedAt`。
- 重建索引时会恢复 AI 标签（审核历史不会恢复，只恢复已通过标签）。

## 7. 库级分析

「库级分析」让 AI 先总结整个库，再生成方案：

1. 选择 Provider。
2. 选择分析方式：
   - **混合（推荐）**：先用元数据做文本聚类，再选代表视频做视觉校验。
   - **仅文本**：只发标题/UP/简介/原始标签，便宜、快。
   - **仅视觉**：只看代表视频封面+帧，贵但准。
3. 采样方式：随机 / 按来源分层 / 按 UP 分层 / 手动选择素材；默认 24 条，最多 **1000** 条。
   - 随机：全库打乱取 N 条。
   - 按来源 / 按 UP 分层：**每个分组保底 3 条**，剩余名额按分组规模比例分配（大收藏夹会多抽几条）。
   - 分组数 × 3 超过设定数量时，样本数会自动提升（上限 1000）；分组太多放不下时会退化为每组 1 条并提示。
   - 文本聚类按模型上下文自适应分批（默认 60 条/批，上下文大时最多 200 条/批），多批**并行**执行；视觉校验最多看 **16** 条代表视频（含 2 条随机补充）。
4. 可选「额外要求」，例如「这是舞蹈收藏夹，重点关注人物形象、服饰、舞蹈风格和 BGM」。
5. 开始分析，查看主题摘要、分类体系、关注点、停用词、生成的提示词。
6. 「保存为方案」后可在「标签方案」继续编辑。

分析结果不会直接改素材库；只有保存为方案并用于打标，审核通过后才会产生本地标签。

**关于输出上限**：库级分析要一次性输出「摘要 + 分类 + 候选标签 + 提示词」，比逐视频打标长得多。
推理模型（如 DeepSeek V4.1 Flash、o 系列）还会先消耗一段 reasoning tokens，实测同一条提示词的推理长度在
1k–6.5k tokens 之间波动。因此文本聚类固定 16000 tokens 起步、视觉校验 12000 起步，遇到截断依次放大到
32000；仍失败时会跳过该批次继续，把原因写进结果备注与「分析历史」。

- 文本批次与代表视频的视觉校验都会开并发泳道，泳道数 = min(「AI 并发数」, 待处理条数)，上限 10。
  1000 条样本 + 16 条视觉校验实测约 4–5 分钟（此前串行要 9 分钟以上）。
- 每轮视觉校验都可能给分类起新名字，合并时会先把常见分类名归一（人物 / 服饰造型 / 舞蹈 / BGM / IP与角色 / 场景与拍摄 / 情绪风格 / 制作与形式 / 主题企划 / 道具与配饰 / 菜系与做法），
  同名分类（例如「鞋袜与身体细节」和「鞋袜与腿部细节」）会合并成一条并合并标签，再裁剪到 12 个、按前缀去掉重复的关注点。
- 失败的分析会留在历史里，点进去可以看到具体错误、tokens 消耗和「重新分析」按钮。

## 8. 搜索与详情

- 侧栏「本地标签」只显示已通过的 AI 标签；点击按该标签筛选。
- 搜索框会同时搜索普通标签和 AI 标签。
- 详情面板新增「AI 标签」分区：按分类展示、显示置信度、可取消通过、可重新打标。
- 视频卡片暂不显示 AI 标签，避免网格信息过载。

## 9. 隐私与安全

- API Key、ACRCloud Secret、自定义请求头使用系统加密存储；不会出现在渲染进程或日志里。
- 只有发起打标/分析时才会把封面、抽帧、必要的 15 秒音频片段发送到你配置的服务。
- 自定义纯模板模式的请求体由你填写，不要把密钥写死在模板里；密钥应放 Key / 请求头字段。
- 模型输出只作为标签文本存储，参数化写入 SQL，不执行。
- 抽帧/音频缓存在 `cache/ai/`，可在「模型与工具」里清理；待审核运行的缓存会被保护。

## 10. 成本与限制

- 每次运行记录输入/输出 tokens、模型请求次数和 ACRCloud 实际请求次数（缓存命中不计）；Provider 配置价格后会显示估算费用。
- 概览、批次卡片、运行记录和审核摘要都会显示请求统计。升级前已有的运行没有历史请求数据，显示为 0。
- 默认每视频 1 封面 + 3 帧，768px；可在「模型与工具」调整。
- 默认并发 2，可调 1–10；库级分析的视觉校验也按这个并发并行走（上限 10）。超过 4 建议先观察是否触发网关限流。
- 抽帧/音频永久缓存，重跑复用；默认保留 30 天，可清理。
- 自定义纯模板模式不支持 tool calling；需要 ACRCloud 请使用 OpenAI/Anthropic/Gemini 兼容模式。
- 库级分析单次请求的输出预算高于逐视频打标（文本聚类 16000 tokens 起步、视觉校验 8000 起步，按需放宽到 32000）；推理模型的 reasoning 也计入这个额度。
- 文本聚类的批大小按模型上下文自适应：输入最多占上下文 40%，单条样本约 130 tokens；没探测到上下文时按 60 条/批。批与批之间并行（跟随「AI 并发数」，最多 6 条泳道）。
- 长视频均匀取帧可能漏掉关键内容；可在标签方案里增加关注点或改用库级分析生成更贴合的方案。
- ACRCloud 可能无匹配或受配额限制；无结果时不会编造曲名。

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| 测试连接 401/403 | Key 无效或无权限；检查 Base URL 与模型名 |
| 429 / 超时 | 降低并发、增加请求间隔、稍后重试 |
| 模型返回不是 JSON | 打开「JSON 模式」；确认 Provider 支持；查看运行详情里的原始响应 |
| 库级分析失败、提示输出被截断 | 推理模型把输出额度用在了推理上：把该 Provider 的输出上限提到 8000 以上，或换非推理模型；也可减少采样数量。日志里会记录 `finish=length` 与响应首尾片段 |
| 视觉请求失败 | 模型可能不支持图片；换视觉模型，或在能力里关闭视觉 |
| ACRCloud 鉴权失败 | 检查 Host / Access Key / Access Secret；用「保存并测试」。只有控制台 JWT 不够，需要在控制台创建 AVR 项目并复制项目凭证 |
| 测试连接返回 2004 | 静音样本无法生成指纹，但鉴权已通过；用真实视频确认 `identify_music` 能返回结果即可 |
| 模型支持图片但显示视觉不可用 | 推理模型在小 token 上限下可能只返回 reasoning；先升级版本或点「探测」应用模型元数据，再重新测试连接 |
| 抽帧失败 | 确认素材库引擎里的 ffmpeg 可用，视频文件存在 |
| 审核页没有结果 | 运行可能在「打标任务」里失败；检查错误原因 |
| 通过后侧栏没出现 | 检查审核状态筛选；刷新素材库；确认标签已通过 |
| 重建索引后 AI 标签丢失 | 确认 `metadata.json` 有 `aiTags`；只恢复已通过标签，审核历史不恢复 |
| 自定义端点工具不可用 | 兼容模式选 OpenAI/Anthropic/Gemini；纯模板模式不支持工具 |
