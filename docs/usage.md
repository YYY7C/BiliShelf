# 使用与快捷键

## 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl / Cmd + K` | 聚焦素材库搜索 |
| `Space` | 播放当前选中的素材 |
| `S` | 播放器内截图（导出原始分辨率 PNG） |
| `Delete` | 将选中素材移入回收站 |
| `Esc` | 关闭播放器 / 弹窗 |

顶栏右侧可切换深色 / 浅色主题。

## 播放与截图

播放器底部控制条右侧的相机按钮（或按 `S`）会在**当前时间点**截图：

- 由主进程调用 ffmpeg 直接从本地源文件解帧，所以是**原始分辨率、无缩放、无弹幕、无播放器 UI** 的 PNG 原图。
- 保存在素材库根目录的 `screenshots/`，文件名形如 `标题_00-15-03.png`（`时-分-秒` 是视频内时间），重名自动加序号。
- 保存后右下角提示分辨率与体积，顶栏出现「截图」按钮可直接在资源管理器中定位文件。
- 迁移素材库时 `screenshots/` 会一起搬走。

## 订阅 UP 主与合集

「来源清单」页右上角的「UP 主 / 合集」可以添加两类订阅；收藏夹与稍后再看仍用旁边的按钮：

输入框支持下面这些写法，粘贴后按「识别」先确认再「订阅」：

| 输入 | 订阅内容 |
| --- | --- |
| `123456789` 或 `mid:123456789` | 该 UP 主的投稿 |
| `space.bilibili.com/123456789` / `.../video` | 该 UP 主的投稿 |
| `m.bilibili.com/space/123456789` | 同上（移动端链接） |
| `space.bilibili.com/123456789/channel/collectiondetail?sid=10001` | 该合集 |
| `space.bilibili.com/123456789/channel/seriesdetail?sid=10002` | 该系列 |
| `space.bilibili.com/123456789/lists/10001?type=season` | 该合集 / 系列（新版链接） |
| `www.bilibili.com/medialist/detail/ml20002` | 该视频列表 |
| `space.bilibili.com/123456789/favlist?fid=20001` | 该收藏夹 |
| `b23.tv/xxxx` | 跟随短链跳转后自动判断 |

- 「识别」会显示 UP 名 / 合集名、封面、总条数和最新 5 条标题；同一个来源用不同链接形式添加只会保留一条。
- 添加后点「同步」才会拉取清单；同步只读取标题、封面、时长、发布时间等元数据，不会自动下载视频。
- 单次同步上限 5000 条，超大 UP 会在识别时提示。
- 每个来源可开启「新增自动下载」：之后每次同步只把**本次新增**的条目加入下载队列。
- 充电专属 / 付费稿件会标成「充电专属」，不计入可下载数量、也不会进队列；下载时才发现需要付费的条目同样会被标记回来。
- 来源卡片上的「参与同步全部」决定点「同步全部」时是否同步它——应用不会在后台定时抓取。

### 时长区间（仅 UP 主投稿）

只订阅某一类短视频 / 长视频时，可以给 UP 主订阅加一个时长区间：

- 在「UP 主 / 合集」面板里填「时长区间（秒）」的最小 / 最大值，留空表示不限；`订阅` 时一并保存。
- 已订阅的来源点详情页顶部「时长 不限 / 1:00–5:00」chip 可以随时修改，回车保存、Esc 取消。
- 超出区间的条目**不会入库**，清单里也看不到；`时长未知`（接口没返回时长）的条目视为不限，不会被误过滤。
- 区间过滤只对 UP 主投稿生效，合集 / 系列 / 视频列表 / 收藏夹 / 稍后再看不受影响。
- 缩小或放宽区间后点「同步」才会重新拉取：放宽会把之前被挡住的条目补进来；缩小会让已入库但超出区间的条目从清单和统计里消失，但不会被标成「已失效」（重新放宽即可恢复）。
- 同步完成的提示里会带上「按时长过滤 N」；这些条目既不占「条目」数，也不会被「全部下载」加入队列。

### 已下载视频的自动关联

订阅 UP 主时，清单里同一 `BV 号 + 分 P` 的视频只要本地素材库已有（包括在回收站里的），会自动关联：

- 卡片上标成蓝色的「**库中已有**」（同来源下载过的显示绿色「已下载」），鼠标悬停有说明。
- 计入「已下载」数量、不计入可下载数量，也不会被「全部下载」或「新增自动下载」重复下载。
- 关联是跨来源的：从收藏夹、稍后再看或别的合集下载过的视频，在 UP 订阅清单里同样会被识别。想重新下载请先删掉素材库里的那条记录（回收站也算已下载）。

### 失效清单与「已补档」

来源清单顶部的「**失效清单**」按钮会跨来源列出所有 B 站已不可播放的条目：

- 「已失效」= 清单里有、但 B 站已经没有（本地也没有副本）
- 「已补档」= B 站没了，但**本地已有副本**（启动时与每次同步后自动关联，标紫色徽标）
- 支持按 BV / 标题 / UP / 来源过滤；点任意一行跳到对应来源，右侧图标直接在 B 站打开
- 「修复本地副本」按钮可手动触发一次关联（正常情况下不需要点，启动与同步时都会跑）

判定依据是 `x/web-interface/view` + `x/player/pagelist` 双接口：`62002 稿件不可见` 单独看会被误判成「审核中」，
必须再看 pagelist——返回 `-404` 才是彻底删除，返回 `cid` 列表则是私密/下架。详见 [失效补档](rescue.md)。

## 侧栏作用域与筛选

侧栏的「全部可播放 / 最近添加 / 文件缺失 / 源已失效 / 回收站」是互斥的**作用域**（状态 + 排序）；
选中标签或文件夹时属于**细分筛选**，作用域高亮会让位，顶栏会显示可清除的筛选条。

## AI 自动打标

左侧「AI 打标」提供一套独立于原始标签的本地标签体系：

- **模型与工具**：配置 VLM Provider、ACRCloud、抽帧/队列参数，并测试连接。
- **标签方案**：设置关注点、分类体系、系统提示词与用户模板；支持全局默认和来源覆盖。
- **开始打标**：选择整个库 / 当前筛选 / 来源 / 选中视频；首次对外部 host 会弹出上传确认。
- **标签审核**：大列表查看原始标签、抽帧和 AI 标签；逐标签或批量通过/拒绝，可内联编辑。
- **库级分析**：先总结整个库，再生成一套通用的标签方案。
- **本地标签**：审核通过的标签出现在侧栏「本地标签」，参与搜索与筛选；详情面板可取消通过或重新打标。

完整配置、隐私说明和常见问题见 [AI 自动打标](ai-tagging.md)。

## 下载任务

「下载任务」页顶部可以批量控制队列：

- **全部暂停**：把所有排队中和正在下载的任务转为暂停；正在后处理的任务会先完成，避免留下不完整的文件。
- **全部开始**：把全部暂停任务重新排入队列；失败和已取消的任务不会自动重试，需要单独点重试。
- **重试全部失败**：把所有失败任务重新排队，适合「一批任务被同一个 CDN 问题打挂，改完设置后一键重来」。

暂停状态和进度会持久化，重启应用后仍可继续。

### 下载失败与代理（重要）

素材下载走的是 B 站 CDN，其中一部分视频会分到 `mcdn.bilivideo.cn` 这类 P2P 节点。实测**系统代理（Clash / v2ray 等 127.0.0.1:7890）会让这些节点超时、连接被重置，或返回 `HTTP 424`**，表现为「CDN 连接中断 / 424 / 读取被截断」。

- 「设置 → 下载 → **下载代理**」默认是 **直连**（推荐）：yt-dlp 会加 `--proxy=`，绕过系统代理。国内网络直连 B 站又快又稳（实测同一视频直连明显更快）。
- 只有必须通过代理上网（海外 / 公司网络）时才选「跟随系统代理」。
- 「设置 → 下载 → **失败自动重试**」默认 2 次：网络类错误（`DOWNLOAD`）会在 5s / 10s 后自动重跑，每次都会重新解析出新的 CDN 地址，绝大多数能成功；312 风控、会员无权限、已下架、磁盘满不会自动重试。
- 失败信息里会写明原因和下一步（例如「CDN 拒绝下载（HTTP 424）…请改为直连」）。
- 画质升级的「检查画质升级」探测同样遵循这个代理设置。

## 后台运行与托盘

默认情况下，点窗口关闭按钮不会退出应用，而是**收进系统托盘**，下载、画质升级、AI 打标都在后台继续。

- 单击托盘图标：打开 / 收起主窗口
- 右键托盘菜单：
  - 显示主窗口
  - 当前「进行中 / 排队 / 已暂停」数量
  - 全部暂停下载 / 全部开始下载（与任务页的批量按钮等价）
  - 打开素材库目录 / 打开日志目录
  - 退出 BiliShelf（只有这里退出才会真正结束进程）
- 首次收进托盘会弹一次提示气泡。
- 想恢复「关闭即退出」，到「设置 → 下载」把 **关闭窗口时收进托盘** 关掉即可。

退出时正在下载的任务会被标记为暂停，下次启动点「全部开始」就能接着下。

## 画质升级

素材库顶栏的「检查画质升级」会逐个探测已下载视频的可选格式：

- 最高分辨率高于当前文件 → 「分辨率升级」
- 分辨率相同但最高码率高出 10% → 「码率升级」

勾选后加入升级队列，会用最高画质重新下载并替换旧文件，标签、文件夹、备注、评分都会保留；
旧文件和旧的封面 / 字幕 / 缩略图会被清理。

升级任务以高优先级入队，会插到批量下载前面执行，因此不必等几千个新下载跑完。

## 整理与修复

「设置 → 素材库 → 整理与修复」提供五个维护动作（执行前建议先点「备份数据库」）：

| 动作 | 作用 |
| --- | --- |
| 补全 cid / 弹幕 | 为旧版本下载的视频回填 cid（弹幕、分 P 去重需要），补下弹幕，并用 ffprobe 重新读取视频流码率 |
| 生成悬停预览 | 为已有视频补 4 秒静音预览片（每个约 200–500KB） |
| 压缩封面缓存 | 把 `cache/covers/` 里的原图压成 640px JPEG |
| 重建封面缩略图 | 把素材库卡片图从视频抽帧换成封面原图的 640px 版本；本地导入等没有封面的视频仍保留抽帧 |
| 清理冗余文件 | 删除 yt-dlp 的 `.info.json`、与 `cover.jpg` 同尺寸的重复缩略图，以及残留的 cookies / 下载暂存 |

## 外观

「设置 → 外观」可以调整：

- 选中视频时是否显示封面虚化背景
- 透明侧边栏
- 背景虚化半径（默认 6px）
- 背景不透明度
- 背景暗化强度

调整后立即生效，配置保存在本机 `%APPDATA%\bilishelf\config.json`。
